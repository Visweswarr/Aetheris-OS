# NGFS Test Fixtures

This directory contains golden test vectors for cross-language validation of the NGFS envelope encryption system.

## Test Vector Files

The following files are generated by the test tools and used to validate that all language implementations produce identical results:

- `key.bin` - 32-byte encryption key
- `nonce.bin` - 24-byte nonce for XChaCha20-Poly1305
- `ad.bin` - Associated data for encryption
- `pt.bin` - Plaintext data to encrypt
- `ct.bin` - Expected ciphertext output
- `tag.bin` - Expected authentication tag
- `header.cbor` - CBOR-serialized encryption header

## Generation

Test vectors are generated using:

```bash
# Go tool
./bazel-bin/go/cli/aeth-enc --generate

# Python tool
python3 tooling/python/encrypt_chunk.py --generate
```

## Validation

Test vectors can be validated using:

```bash
# Go tool
./bazel-bin/go/cli/aeth-enc --fixtures tests/ngfs/fixtures

# Python tool
python3 tooling/python/tests/test_vectors.py

# Rust tests
bazel test //tests/ngfs:ngfs_encryption_test
```

## Cross-Language Compatibility

All implementations must produce byte-identical outputs for the same inputs to ensure:

1. **Deterministic Encryption**: Same plaintext + key + nonce = same ciphertext
2. **Schema Stability**: CBOR encoding is consistent across languages
3. **Algorithm Correctness**: XChaCha20-Poly1305 implementation is identical

## Test Data

The test vectors use deterministic, non-random data:
- Key: `[1, 2, 3, ..., 32]`
- Nonce: `[100, 101, 102, ..., 123]`
- AD: `"associated data for testing"`
- Plaintext: `"plaintext data for encryption testing"`

This ensures reproducible test results across different environments and builds.
